# ADR 010 — LLM Processing Location, Retention, and Data Handling (Research Only)

**Status**: Proposed Architecture & Procurement Policy (Research Only — Zero LLM Runtime Calls in Q-0)  
**Date**: 2026-11-12 (Stage Q-0d — Q7; Official Documentation Verified 2026-11-11)  
**Decision makers**: Engineering, Security & Legal Architecture Team

---

## Context

When MeetMind AI introduces generative reasoning in future components (§7 Agent Orchestration, §10 Pre-Meeting Brief, §11 Live In-Meeting Strategy Tier 2, §12 Post-Meeting Workflows), customer transcripts and read-only Jira/GitHub/incident evidence will be sent to third-party foundation model APIs.

MeetMind AI targets both general engineering organizations and regulated enterprises (including India DPDP-sensitive, fintech/BFSI-adjacent, and enterprise customers demanding strict Zero Data Retention (ZDR) and in-region processing). Furthermore, ADR-008 already mandates that §6 Trigger Classification (`<= 200 ms` P50) MUST NOT invoke any remote LLM API. Therefore, this ADR establishes strict vendor/endpoint eligibility rules based **solely on verified official provider documentation** (citing exact page titles, URLs, and access dates, and marking undocumented claims `UNVERIFIED`).

## Architectural Decision & Tenant Compliance Rules

1. **Unpaid Keys & Consumer Endpoints Strictly Prohibited**: MeetMind AI MUST NEVER run production, beta, or design-partner traffic on Google AI Studio Unpaid quota (`UNPAID` terms allow training & human review) or Anthropic consumer endpoints.
2. **Default Enterprise Baseline (Global / US-Pinned Tenants)**:
   - Require active ZDR contracts + non-training DPAs before enabling Tier-2/Post-Meeting LLMs (`store=false` enforced client-side on every request, no Files/Batches/Assistants stateful endpoints, no secrets or customer PII inside JSON schema field names/enums).
   - Both Anthropic `/v1/messages` (under Sales-enabled ZDR, excluding Covered Models) and OpenAI `/v1/responses` (with `store=false` + ZDR) satisfy global/US ZDR, subject to live Lane 2 TTFT benchmarking against the `<= 4000 ms` P95 budget.
3. **India-Residency / DPDP-Strict Regulated Tenants**:
   - **Anthropic first-party API (`api.anthropic.com`) and Public Gemini Developer API (`ai.google.dev`) are INELIGIBLE** for India in-region inference guarantees (Anthropic lacks `"in"` `inference_geo`; Gemini Developer API explicitly permits cross-country transient caching).
   - **Eligible Paths for India Tenants**:
     - **Option A — OpenAI India Endpoint (`https://in.api.openai.com/v1`)**: Permissible **only** with approved active OpenAI ZDR, project pinned to India, `model="gpt-6-luna"` only, `/v1/responses` or `/v1/chat/completions` (`store=false`), and zero hosted tools. Note that Realtime/Audio models do NOT run in India (already handled in-region by ASR per ADR-007 / ADR-012).
     - **Option B — Google Cloud Vertex AI / Agent Platform (`https://asia-south1-aiplatform.googleapis.com`)**: Permissible once the GCP project verifies (i) target Gemini model availability in `asia-south1` (`UNVERIFIED` live SKU matrix until project verification), (ii) BigQuery Request-Response logging disabled, (iii) `store=false` on Interactions API, (iv) Session Resumption disabled, (v) zero Google Search/Maps grounding, and (vi) `/cacheConfig` patched to `disableCache: true` (or `EPHEMERAL` if RAM-only prompt caching is approved by the tenant's security review).
4. **No Silent Cross-Region Fallback**: Extending ADR-007's `Fail-Fast Residency Invariant`, if an India-pinned tenant's regional LLM endpoint (`in.api.openai.com` or `asia-south1-aiplatform.googleapis.com`) fails or is misconfigured without ZDR, the intelligence pipeline MUST fail closed and emit an explicit degradation/abstention rather than falling back to `global` or `us` endpoints.
5. **Pre-Implementation Latency Gate**: Before selecting the production model for Lane 2 (Tier-2 Reasoned Cards), benchmark live SSE TTFT + `strict` JSON schema tool completion P50/P95 from the deployment VPC/host against real meeting prompts (target full Tier-2 `t0_capture -> ui_render <= 4000 ms` P95).
